# 【站点名称】网络安全应急响应预案

> 依据《网络安全法》《数据安全法》及公安部令第176号第七条第六项制定。
> 版本：V1.0　编制：站点管理员　实施日期：【YYYY年MM月DD日】

## 一、预案目标

在发生网络安全事件时，快速响应、控制影响、恢复业务、留存证据，最大限度
降低损失并满足法律合规要求。

## 二、事件分级

| 级别 | 定义 | 示例 |
|------|------|------|
| Ⅰ级（重大） | 核心业务瘫痪 / 大规模数据泄露 / 网站被篡改 | DDoS 打瘫服务、数据库被拖库、首页被篡改 |
| Ⅱ级（较大） | 部分功能受损 / 少量用户数据受影响 | 上传服务故障、个别账号被盗 |
| Ⅲ级（一般） | 影响轻微，可快速恢复 | 偶发接口错误、垃圾评论刷屏 |

## 三、应急组织与职责

| 角色 | 职责 |
|------|------|
| 应急指挥（站长） | 决策、对外沟通、必要时向公安网安部门报告 |
| 技术处置（技术管理员） | 止损、排查、修复、恢复 |
| 证据保全（审核员） | 记录事件时间线、备份日志与现场证据 |

## 四、处置流程

### 4.1 Ⅰ级事件流程

1. **止损（0-1小时）**：立即切断受影响服务（下线被篡改页面、隔离异常服务器、暂停外链）；
2. **取证（1-2小时）**：备份系统日志、访问日志、数据库快照（本平台日志自动留存+归档）；
3. **排查（2-8小时）**：定位入侵/攻击路径，检查后门与异常账号；
4. **修复（8-24小时）**：修补漏洞（同步录入「漏洞管理」）、重置全部凭据、恢复数据；
5. **恢复（24-48小时）**：逐步恢复服务，持续监控；
6. **报告（48小时内）**：按规定向属地公安网安部门报告，留存报告记录。

### 4.2 Ⅱ级流程

参照Ⅰ级压缩执行，24小时内完成排查与修复，72小时内形成书面总结。

### 4.3 Ⅲ级流程

技术管理员直接处置，修复后在漏洞管理/事件台账中登记。

## 五、事件报告与台账

1. 每次应急响应后 3 个工作日内形成《安全事件报告》：事件经过、影响范围、
   处置措施、整改方案、责任认定。
2. 建立安全事件台账，记录事件时间、级别、处置人、处置结果，至少保留 2 年。
