# 安全防护 / 成本闸门 / 内容玩法：15 项缺口落地说明（v3.19.0）

> 来源：`docs/gap-audit.md` 里剩下的 15 项。本文只写**怎么落地、边界在哪、怎么用**，
> 不重复需求背景。设计上的一条总原则：**能自动化的只到「提醒 + 排队 + 打标」，钱与封禁永远留给人**。

---

## 一、安全防护（6 项）

### 1. SQL 注入蜜罐（gap-audit #3）

**前提先说清**：真实业务链路全部参数化查询，SQL 注入**打不穿**。所以这个蜜罐不是"防注入"，
而是**钓鱼式假入口**：

| 假入口 | 返回什么 |
|---|---|
| `/api/v1/query` | 仿 MySQL 错误回显（报错注入者会以为"有戏"） |
| `/api/v1/login` | 永远"登录成功" + 假管理员 token（`hp.NVS-CANARY-SQLI-*`） |
| `/api/v1/admin/tables` | 假表结构（8 张假表 + 行数） |
| `/api/v1/export/users` | 6 条假用户（`@example.internal`、假 bcrypt） |
| `/legacy/db.php`、`/db/query` | 同上，走通用响应 |

- 特征识别 10 类：`union_select` / `time_blind` / `error_based` / `stacked` / `schema_probe` /
  `file_access` / `tautology` / `quote_break` / `comment_bypass` / `boolean_probe`
- 风险分：无命中=40（探路），命中按最高特征打分（50~95），**≥3 个特征 +5**（说明在用工具）
- 事件 `kind = sqli_hit / sqli_probe`，payload 全量落 `body_snippet`，可反哺 WAF 规则
- 等级 `off`/`low` 时这些路径与普通 404 无差别（不暴露蜜罐存在）
- 后台：`GET /api/admin/honeypot/sqli`（命中/探路数 + 按假入口分组）

**边界**：假数据一次生成、与真实库零关联；金丝雀 `NVS-CANARY-SQLI-*` 用于泄露溯源。

### 2. JA3 / JA4 与 WebRTC（gap-audit #4）

**必须先承认的现实**：JA3/JA4 来自 TLS ClientHello，**只有终止 TLS 的那一层算得出来**。
本进程通常在反代后面，看到的是明文 HTTP。所以：

| 部署形态 | 采到什么 | 表现 |
|---|---|---|
| 反代透传 `X-JA3-Hash` / `X-JA4`（推荐） | JA3、JA4 | `tls_source=proxy_header` |
| 本进程直接终止 TLS | 只记 TLS 版本 | `tls_source=direct_no_ja3`（明确"没算"，不伪造） |
| 都没有 | 什么都不记 | `tls_source=missing`，后台诊断提示"反代未透传" |

- 新列：`honeypot_fingerprints.ja3 / ja4 / tls_source / tls_version / webrtc_ips`
- WebRTC：验证页 JS 用 `RTCPeerConnection` 收 ICE host 候选（现代浏览器多为 mDNS `.local`，
  能拿到真内网 IP 的场景在减少），**只作关联线索，不作判定依据**
- 后台：`GET /api/admin/honeypot/tls` 给采集率、诊断结论与 nginx/caddy 配置模板

### 3. 注册门槛与设备指纹（gap-audit #14）

`server/gate` 把四道闸门收在一处，处理器只调 `CanRegister` / `CanPost`：

```
邀请码（挡批量注册）
  → 设备指纹（挡同机小号，X-Device-Id 优先，ip+ua 兜底）
  → 账号年龄（挡注册即刷：发文/评论分别设阈值）
  → 新号每日上限（挡慢速刷）
  → 蜜罐命中 IP / 临时邮箱（挡已被识别的攻击者）
```

- 配置默认**全关**（升级不改变现有站点行为），后台「注册门槛与防刷」一键开
- 邀请码：限次、限时、可作废；消费在事务里 `used < max_uses` 条件更新，防并发超发
- 已接入三处：注册（含失败回滚用户）、评论、章节发布
- 后台还能看「同设备账号数排行」，**accounts≥3 是重点关注对象**

**边界（写在文档里也是防甩锅）**：`X-Device-Id` 可被清 localStorage / 伪造，
所以设备指纹是"提高成本"，不是"绝对防御"。真正硬的是邀请码与蜜罐 IP。

### 4. 充值风控联动（gap-audit #9）

**在入账前打分**，三种处置：

| 处置 | 行为 | 适用 |
|---|---|---|
| `allow` | 正常入账，事件归档为已放行 | 正常用户 |
| `hold` | **入账**但打标，进人工复核队列 | 有可疑信号但不确定 |
| `block` | **不入账**，进人工复核队列 | 黑卡/盗刷/刷单的典型形态 |

六条规则（分数可配）：蜜罐高风险 IP +40、同设备≥3 账号 +25、10 分钟≥5 笔 +30、
退款率超阈值 +35、新号(<2h)大额 +20、单笔≥1000 元 +10。

**两条铁律**：
1. **绝不自动扣回已到账余额**——钱的事必须有人判断，程序只负责"不让可疑的钱继续进来"；
2. `block` 时回调仍返回渠道成功应答（避免无限重试打爆队列），同时写事件让管理员看到
   "有一笔钱收了但没入账"，避免静默丢单。

### 5. 警方联动工单（gap-audit #6）

- 建单（类型/优先级/截止）→ 派单 → 进展 → 结案
- **结单必须写结论**（不留结论的结单等于没办），全流程写操作日志
- 统计口径：待受理/处理中/待补材料、**超期未结**、**未派单**
- **工单只存证据引用**（蜜罐会话 ID / 取证包名 / 帖子 ID），不存证据本体——
  避免工单变成"永久证据仓库"绕过各自模块的留存 TTL

### 6. API Key 告警口径（requirements-audit「HMAC 指纹与告警未做」）

| 能力 | 实现 |
|---|---|
| HMAC 审计指纹 | `HMAC-SHA256(NVS_KEY_AUDIT_SECRET, prefix:plain)[:32]`，不存明文也能对号 |
| 多 IP 提醒 | 同 key 24h 内 ≥3 个 IP → 告警（**只提醒不封禁**，移动网络切换会触发） |
| 异常解密告警 | 解密失败写 `decrypt_fail`（密钥轮换/密文被改） |
| 封禁后仍使用 | 已封禁 key 再被用 → `banned_use` |

## 二、成本闸门（4 项）

### 7. 全站总预算 + 高峰排队（gap-audit #12）

已有的是「单次上限 / 每日个人限额 / OC 群级预算」，缺的是平台级总闸门——一个热帖被刷、
一次 AI 互聊跑飞，成本照样烧穿整月预算。

- **日 / 月代币上限**：`HardStop` 关闭时"到线只告警"（适合先观察），开启时直接拒绝并给明确提示
- **并发闸门**：超出并发就排队（`AcquireSlot` + 超时），排不上返回"忙"，
  而不是把上游打到 429 连坐所有人
- **峰时上限**：高峰时段用更小的并发；**峰时上限高于全站上限会被自动钳制**
  （否则"高峰"反而更宽松，是配置错误）
- 记账口径：**按 `AiCallLog.Cost` 实际结算值累计**，估算只用于"这一次会不会超"的预判

### 8. 三维交叉限流（gap-audit #15）

| 维度 | 挡什么 |
|---|---|
| 用户 × 模型 / 分钟 | 一个人死磕一个贵模型（把贵模型当免费额度刷） |
| 用户 / 分钟 | 一个人换模型刷 |
| 模型（全站）/ 分钟 | 一群人打一个模型 → 上游限流连坐 |

滑动窗口按秒分桶、10 秒清一次过期桶。**单实例内存计数**——多实例部署时每实例各限一份
（近似限流，后台文案已写明，不假装是集群精确限流）。

### 9. 转化漏斗（gap-audit #13）

六段（去重用户，窗口可调）：触达 → 使用 → 免费额度用尽 → 创建订单 → 付费成功 → 复购(≥2 笔)。

每段同时给**单步转化率**与**相对触达累计率**（只看相邻会误判：前面漏太多，后面再高也没用），
并直接输出"最弱一跳"结论，省得对着一堆百分比自己猜。

### 10. 语音 / 音乐（gap-audit #18）

- `aiclient/audio.go` 只做 OpenAI 兼容 `/v1/audio/speech`（TTS 与音乐同一入口，靠 model 区分）
- 三条硬约束：**2000 字上限**（TTS 按字符计费，不限就是成本黑洞）、
  **必须有 `kind=audio` 模型**（没有就明确报"未配置"，不偷偷回落 chat 模型假装生成）、
  **产物随机名落 uploads**（不可枚举、不覆盖他人）
- 计费：免费额度优先，否则扣 `PriceCall`
- 阅读器「朗读」按钮：取当前章纯文本 → 合成 → 播放，离开页面自动停止

## 三、内容玩法（5 项）

### 11. 自定义导航菜单（gap-audit #20）

- 两级树（父/子），排序、可见、需登录、仅管理员、小标（NEW/HOT）
- **协议白名单**：只允许 `http(s)` 与 `/` 开头的站内路径；`javascript:` / `data:` /
  `vbscript:` / `file:` / 协议相对 `//host` 一律拒绝
- 前端导航栏按 `window.open` / `router.push` 分流，外链强制 `rel="noopener noreferrer"`

### 12. 轮播 / 签到 / 访客（gap-audit #23）

- **轮播**：图 + 跳转 + 排序 + 时段；**后端过滤时段**（不信任前端），首页作为 `carousel` 区块类型
- **签到**：每日一次 + 连签加成（封顶），奖励进既有代币账本（不新开账）
  - 幂等靠 **`(user_id, date)` 唯一索引 + 先落记录后发币**；发币失败回滚记录
- **访客设置**：未登录能否浏览/搜索、最多看几章、是否展示访问量、提示文案；附 14 天 PV/UV

### 13. 自定义表情包（gap-audit #22）

- 用户上传图片 → 注册 `键 → URL`，气泡里写 `[键]` 渲染为 `<img class="sb-emote-img">`
- **键全局唯一**：气泡由服务端渲染，没有"当前用户"上下文；同名键会渲染成别人的图，
  所以冲突直接拒绝并提示改名（比静默覆盖诚实）
- URL 白名单：`/uploads/` 或 `http(s)`；`javascript:` / `data:` / `blob:` / `file:` 拒绝
- 内置表情词典不受影响（自定义优先匹配）

### 14. OC 角色卡 / 世界书互通（gap-audit #24）

- **导出**：酒馆 V2（`chara_card_v2`）JSON；自家字段（外貌/说话风格/养成状态/表情映射）
  放 `extensions.nvs`；角色自带世界书走 `extensions.character_book`
- **导入**：V2 优先、V1 扁平兼容；`character_book` 自动创建世界书并逐条落库；
  **未知字段保留**到 `raw`（不丢用户数据）
- 前端：角色卡行内「导出」、工具栏「导入酒馆卡」（选文件或粘贴 JSON）

### 15. 思维导图（gap-audit #19）

- `AI_ACTIONS` 新增 `mindmap`：提示词强制输出一个 ` ```mermaid ` 代码块，
  首行 `mindmap`、2~4 层、节点 ≤12 字、不编造原文没有的内容
- 阅读器已有 Mermaid 渲染，插入正文即出图

## 四、仍未做（明确边界，不是漏做）

| 项 | 原因 |
|---|---|
| AI 出图**附件上传 / 历史导出**（gap #17） | 本轮 15 项清单未包含；与绘画任务队列耦合，需单独设计 |
| 气泡**长按互动**（gap #22 的一部分） | 属交互设计，非能力缺失 |
| **直播入口**（gap #23 的一部分） | 需要流媒体链路，与当前"单二进制 + 静态产物"架构不同层 |
| JA3 **在本进程内计算** | Go 标准库不暴露 ClientHello 原始字节；需自己写 TLS 层或依赖反代 |
| 集群级精确限流 | 单实例内存计数；要做精确需引入 Redis，与"无外部依赖"取舍冲突 |
