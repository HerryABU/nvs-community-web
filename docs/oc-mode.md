# OC 模式群组 · 设计与实现

> OC = Original Character。用户在群组里以**角色卡**身份互动（人扮演或 AI 扮演），
> 用**世界书**维持设定一致，AI 角色之间也可以互聊（多智能体角色扮演），
> 产物（对话流）可**一键发布为话本小说**。
>
> 定位：OC 是群组的**玩法层**，不是「绕过群组治理的例外」——
> 群组额度、群主权限、先审后发、举报、取证、软删除留证，全部适用。

---

## 1. 顺序：为什么先有多人联合小说

多人联合小说（v3.11，见 `docs/novel-collaboration.md` + `docs/novel-version-control.md`）
已经跑通了协作叙事的地基：成员/角色/权限、章节轮次、版本与冲突、发布审核、AI 标识、限额、审计。

OC 群组只是把「真人协作者」换成「AI 角色/智能体」、把「章节」换成「对话流」、
把「分工」换成「调度器」——**轮子复用，增量是玩法层**。

## 2. 数据模型（`server/oc`）

| 表 | 作用 |
|---|---|
| `oc_characters` | 角色卡：名称/头像/人设/外貌/性格/背景/说话风格；归属用户（可绑定到群）；可见性 private/public；审核状态 |
| `oc_world_books` | 世界书：标题/简介/归属；`oc_world_entries` 条目化条目（分类：世界观/势力/地点/规则/事件）+ 版本 |
| `oc_group_settings` | 群级 OC 配置：开关、模式、审核等级、窗口大小、预算、最大轮次 |
| `oc_agents` | 群内 AI 角色：角色卡 + 绑定模型 + 提示词模板 + 发言策略 + 预算 + 启停 |
| `oc_flows` | 对话流/剧情线：群 + 参与角色 + 当前轮次 + 状态（running/paused/stopped） |
| `oc_turns` | 单轮发言：角色/模型/上下文/输出/token/费用/审核状态 |
| `oc_windows` | 审核窗口：窗口内发言区间 + 审核结果 + 命中规则（**多条一起审**） |
| `oc_budget_usage` | 群级/角色级预算消耗（按日/按流累计） |

## 3. 群组 OC 模式

| 模式 | 标识 | 说明 |
|---|---|---|
| 混合 | `mixed` | 人与 AI 角色同群互动（默认） |
| 纯 AI | `ai_only` | 群内只有 AI 角色互聊，用户是「导演」（可推进/喊停/改设定） |

- 角色卡可跨群复用（`oc_characters` 归用户，`oc_agents` 是「角色卡 × 群」的绑定实例）。
- 用户在同一群里可切换身份（本人 / 某个自己的角色）。

## 4. 发言调度器

策略（`oc_flows.schedule`）：

| 策略 | 说明 |
|---|---|
| `round_robin` | 按参与角色顺序轮转（默认，最稳） |
| `random` | 随机点名（更有戏剧性，也更不可控） |
| `trigger` | 命中触发词（角色名/@）才发言 |
| `manual` | 仅用户手动推进 |

硬约束（防无限循环/烧钱）：`max_turns`（默认 40）、单轮超时、
用户可 `pause` / `resume` / `stop` / `step`（单步一次）。

## 5. 预算（防成本失控）

- 三道闸门：**单次调用上限**（沿用 AI 体系）、**群级每日预算**、**单流/单角色上限**。
- 超额：暂停对话流 + 标记 `budget_exceeded` + 前端提示；不静默继续烧。
- 计费走现有账本：`AiCallLog` + 免费额度 + 代币结算，scene 记 `oc_turn`。

## 6. 审核：多条一起审（窗口审核）

- **窗口**：按 N 条（默认 5）/ N 轮 / N 字切一个窗口，站长/群主可配。
- **审核对象**：窗口内多条发言 + 相关角色卡/世界书设定 + 上下文摘要（不是只看单条）。
- **时机**：
  - `pre`（先审后发）：严格模式，攒满后统一审，通过才展示
  - `post`（先发后审）：宽松模式，命中则标记/隐藏/回滚 + 留证
- **审核等级（站长可选，框架中性）**：
  - `strict` 严格：每条窗口都审，命中即停流并人工复核
  - `loose` 宽松：只审公开分享内容与举报命中内容
  - `redteam` 红队：**故意放开拦截、只记录**，产出安全资产
- **红队模式的四条边界（必须守住）**：
  1. **隔离**：不进社区内容流、不参与搜索/推荐、不对外分享
  2. **授权**：站长开启需确认范围与责任人（写入审计）
  3. **记录**：prompt/模型/输出/命中规则全进安全审计库，可导出报告
  4. **不教唆**：产出是「哪些设定/prompt 会激发违规」的安全资产，不是攻击教程
- 审核实现：`security.ScanBadWords` / `ApplyBadWords`（规则）+ 可选审核模型（从池子选独立模型，避免自审自）。

## 7. AI 角色怎么接（复用现有 AI 体系）

| 现有能力 | OC 用法 |
|---|---|
| `models.AiAgent` | AI 角色 = 智能体实例（角色卡即人设） |
| 提示词/模板 | 角色卡字段 + 世界书条目 = 模板变量注入 |
| 模型池 | 每个 AI 角色可绑不同模型，走池子路由 |
| 计费/免费额度 | 每轮发言计费，scene=`oc_turn` |
| `realtime` 群频道 | 新发言广播事件 `oc.turn`；暂停/停止广播 `oc.flow` |
| 审计 | 每轮记录角色/模型/token/费用/审核结果 |
| 发文限额 | 一键发布计入每日发文限额（按发起人） |

## 8. 一键发布为话本小说

对话流 → 章节转换器（复用现有作品/章节发布链路 + 话本形态）：

1. 选目标作品（新建 / 追加）+ 选轮次范围
2. 形态：`dialogue`（对话体，即话本气泡：`角色：台词`）/ `narrative`（叙述体）/ 可选 AI 润色
3. 生成设定集：角色卡 → 角色介绍；世界书 → 设定页（可选公开，走审核）
4. **必须过公开内容审核 + AI 标识必填**（`creation_method=ai` / `human_ai_assisted`）
5. 来源追溯：章节记 `source_type=oc_flow` + 来源流 ID，可导出
6. 计费与限额：润色消耗代币；发布计入每日发文限额
7. 归属：发起人 = 章节作者；参与者署名沿用协作规则（`collab`）

「一键」= 一键导入 + 一键提交审核，**不是一键绕过审核**。

## 9. 权限

| 动作 | 谁能做 |
|---|---|
| 建/改自己的角色卡、世界书 | 本人 |
| 群内启用 OC、配模式/审核等级/预算 | 群主/管理员 |
| 配 AI 角色（绑定角色卡与模型） | 群主/管理员 |
| 推进/暂停/停止对话流 | 群主/管理员 + 流的发起人 |
| 以角色身份发言 | 群成员（角色须属于本人） |
| 一键发布 | 群主/管理员/流发起人（受未成年与限额约束） |
| 公开角色卡/世界书 | 本人发起 → 平台审核 |

未成年人（`minor_mode`）限制：不建 OC 群、不绑 AI 角色、不启用 `ai_only`、不发布。

## 10. 风险边界（写死在实现里）

1. 成本：三道预算闸门，超额即停
2. 无限循环：最大轮次 + 超时 + 手动停
3. 违规互相激发：窗口审核 + 命中停流 + 人工复核
4. 未成年人：建群/绑 AI/发布三重限制
5. 内容标识：每条 AI 发言标角色 + 模型；发布作品标 AI 参与
6. 数据隔离：未公开的角色卡/世界书仅本人与所属群可见；删除留证
7. 版权：角色卡/世界书提供举报入口 + 软删除留证，平台不做版权判断

## 11. 借鉴来源（落地取值说明）

### 11.1 SillyTavern（酒馆）角色卡 V2 + Lorebook

| 借鉴点 | 本项目落地 |
|---|---|
| 角色卡字段：`description`（常驻）/ `personality` / `scenario` / `first_mes` / `mes_example` / `system_prompt` / `post_history_instructions` / `creator_notes` / `alternate_greetings` | `oc_characters` 对应 `persona` / `speech` / `scenario` / `first_message` / `mes_example` / `system_prompt` / `post_history` / `creator_notes` / `greetings` |
| 「描述是固定税、世界书是条件开销」 | 人设常驻注入；世界观拆成条目按键触发（`server/oc/lore.go`） |
| 条目字段：`keys` / `secondary_keys` / `selective` / `logic` / `constant` / `insertion_order` / `priority` / `position` / `depth` / `probability` / `case_sensitive` / `group` | `oc_world_entries` 一一对应；另加 `enabled` / `whole_word` |
| 书级 `scan_depth` / `token_budget` / `recursive_scanning` | `oc_world_books` 同名三字段 + 一轮递归扫描 |
| 宏 `{{char}}` / `{{user}}` | `ExpandMacros`，对方名取最近一个非本角色的发言者 |
| `mes_example` 是最强的风格锚点 | 提示词里单独成块「对话示例（照此风格，不要照抄内容）」 |

位置对齐：`0=角色定义前`、`1=角色定义后`、`4=对话内`（酒馆 `before_char` / `after_char` / `at_depth`）。

### 11.3 团子 APK 反编译结论（供后续逆向参考）

在 WSL 中对 `xiaotuanzi_0.1.0(86).apk` 做了静态分析：

- 壳是 **React Native + Expo**（`assets/index.android.bundle` 为 Hermes 字节码，`res/values/strings.xml` 只有 RN/Expo 库文案，`app_name=小团子`）。
- `hbc-disassembler` 反汇编出的 hasm 里**没有业务中文与业务字段**（只有库代码：reanimated、react-navigation、expo 等），
  说明业务 bundle 走 **Expo OTA 动态下发**，静态包里拿不到产品逻辑。
- 可见资产只有 `s.mytuanzi.com` 的静态页（terms/privacy）与少量素材，无 API 路径。
- 结论：**产品层借鉴只能来自公开资料**（App Store 更新日志 + OC 圈文化），实现细节需抓包或等 OTA bundle 落地后才能反推。
